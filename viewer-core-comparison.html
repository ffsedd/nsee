Should the viewers share a core?

Recommendation: small core

The overlap is real in viewport math and display caching; the image models and user workflows are different enough that sharing the apps would create coupling.

nsee

A small general raster viewer and editor.

  • Pillow loads RGB or grayscale files into NumPy arrays.
  • Integer zoom is inverse sampling: each screen pixel represents a zoom-sized source step.
  • ImageView caches one sampled PhotoImage for the current array and zoom; pan changes its canvas position.
  • Selection, crop, save, JPEG rotation, and directory navigation belong to this app.
Existing boundary: geometry.py · view.py · imagelist.py · io.py · ops.py

rdxkit tile_viewer

A scientific grayscale and PBF inspection tool.

  • PBF loads as uint32; common formats are converted to grayscale.
  • Zoom is a direct float scale; zoom-in repeats pixels and zoom-out samples them.
  • Pan currently normalizes, resizes, creates a PhotoImage, clears the canvas, and redraws on each motion.
  • Percentile/range normalization, histogram, statistics, and PBF handling are domain features.
Existing boundary: tile.py · imageio.py · utils.py · gui.py

Share these primitives

Viewport math

A toolkit-independent transform for image coordinates, screen coordinates, pan offsets, zoom-at-cursor, and selection bounds. Represent scale as screen pixels per image pixel; nsee can map its current inverse integer zoom to scale = 1 / zoom.

Display pipeline

Small NumPy helpers for nearest-neighbor sampling, grayscale normalization, and a bounded cache keyed by source revision, display settings, and scale. UI adapters keep Tk PhotoImage work out of the core.

Image-source contract

A minimal protocol for shape, dtype, pixel/tile reads, and source identity. Keep eager raster arrays and PBF-specific loading as separate adapters; defer tiled/region reads until image sizes require them.

Keep app features localKeep file navigation, crop/save/rotate in nsee. Keep PBF loading, intensity normalization, histogram, and statistics in rdxkit. Do not share Tk widgets, window layout, or application controllers.

Decision

Build the core only if both viewers will remain actively maintained. Start with a small viewer_core package containing pure transforms and display-array utilities; leave loaders and GUI adapters in each project. If this is only to deduplicate a few functions, use tests and copy the stable math instead of adding a separately versioned dependency.

Evidence inspected: nsee geometry.py, view.py, io.py; rdxkit tile.py, imageio.py, utils.py, and gui.py. Both source trees were read only.
